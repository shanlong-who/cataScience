## Fix release

This release fixes the check ERRORs on the Debian flavors reported by
Kurt Hornik on 2026-08-05 (deadline 2026-08-26).

> Having package code which is run as part of the checks and attempts to
> write to the user library violates the CRAN Policy

Cause: the app rendered its markdown lesson pages with
`htmltools::includeMarkdown()`, which passes the file path to
`markdown::mark()`. Since markdown 2.0, `mark()` rewrites an input *file*
in place when it runs under `R CMD check` (to normalize YAML for
litedown). The test suite sources the bundled app from the installed
package directory, so `mark()` tried to write into the package library,
which is mounted read-only on the Debian check machines.

Fix: the lesson pages are now rendered from text
(`markdown::mark(text = )`), which never writes to the file system. The
generated HTML is identical; the test suite verifies that building the
whole UI works and I have additionally verified locally that it no longer
modifies any file under `R CMD check` conditions.
